# 按本机路径证据识别监听服务归属

Environment Scan 只观察 TCP 监听服务，独立判断其 Local Service Attribution 与 Python、Node、Bun、Go、Rust、Java 类型；未知类型不会阻断已有的项目证据，多语言仓库中的进程分别判断。

项目标题取最近 Git 根目录名，运行目录取最近对应项目清单目录；遇到嵌套 Git 根即停止向外查找。无 Git 时统一使用清单目录名，不采用清单内部名称。清单证据覆盖 `pyproject.toml`、`package.json`、`go.mod`、`Cargo.toml`、Maven 和 Gradle。缺少项目证据时从可执行文件所在 `.app` 识别宿主应用，否则保持未知。

运行时优先依据真实可执行文件名，再使用监听进程名，包含 `bun.exe`。任意名称的原生二进制仅在其所在项目的最近清单明确且唯一为 Go 或 Rust 时推定类型；这不是二进制语言鉴定，外置构建或混合清单保持类型未知，不通过程序名称、端口或整个仓库的主语言猜测。

Java 按需读取 macOS 提供的结构化 argv，只从 JVM 的 JAR、classpath/module-path 选项提取存在的路径；主类或模块后的参数属于应用，不参与识别。明确的启动路径优先于工作目录，多个项目候选冲突时保持未知。独立 JAR 或二进制没有项目证据时只显示文件路径，不把部署目录当源码项目。

## Consequences

- 2026-09-08 的确认范围替代原先禁止读取参数的限制：argv 仅在内存中按需读取，不解析尾随环境变量；快照和 UI 只保存类型、项目及文件路径，不保存或展示完整参数，不遍历父进程，不执行项目程序或构建命令。
- 原生 App 进程优先使用可执行文件所属 `.app`，不使用其继承的工作目录推定项目；明确的解释器进程仍允许真实项目目录优先于宿主 App。项目查找在用户主目录之前停止，未知类型还必须有项目清单，不能仅凭安装目录的 `.git` 推定项目。
- 归属、类型或文件路径不同的服务不合并，复用已有品牌资源。
- 路径或参数不可读时静默回退到其他可用证据，不产生 Scan Notice；旧快照缺少新增可选字段时仍可读取。
