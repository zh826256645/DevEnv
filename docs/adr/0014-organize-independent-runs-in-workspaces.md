# 用工作区组织项目与独立运行配置

运行配置不再以项目记录为存在前提：用户通过具有稳定身份和名称、但不对应磁盘目录的 Workspace 组织项目记录和运行配置，两类记录各自只属于一个工作区。配置可以关联项目并保留建议来源，但删除项目只使关联失效，不删除配置；这避免以项目生命周期限制独立命令的管理。

## 已确认的决定

- 提供默认工作区，旧项目和配置迁入其中，保留命令、来源和工作目录语义；本期不提供跨工作区移动或复制。
- 工作区切换器下设项目与运行页签；本机工具和环境保持全局。切换工作区不停止运行。
- 项目是 App 内的独立记录，不以目录路径作为身份；同一磁盘目录可以对应多个项目，并分别加入不同工作区。
- 同一工作区也允许用户显式创建指向同目录的多个项目；项目名称默认取目录名并可修改，自动扫描不因重复发现同目录而新增项目。
- 配置只能关联所属工作区内的项目。删除项目后重新添加相同目录会创建新身份，不自动恢复旧关联或认领来源；用户可以手动重新关联。
- 删除项目后的扫描忽略只作用于当前工作区，不影响其他工作区发现该目录，也不影响仍指向该目录的其他项目记录。
- 工作目录支持绝对路径和项目相对路径；未指定时，关联项目默认使用项目目录，未关联默认使用当前用户目录，实际目录在每次执行时解析并冻结。
- 项目关联失效后置灰，阻止新的启动，用户显式解除关联后才可启动。解除关联将原项目相对目录转换成绝对目录，不静默回退用户目录；实际目录不存在则启动失败。
- 项目相对路径允许越出项目目录；项目目录只是解析基准，不是执行边界，启动前仍检查实际目录存在且可访问。
- 删除项目保留配置及当前运行，后续启动需先解除失效关联。删除工作区连带删除其中保存的项目记录和运行配置，不删除磁盘目录；删除工作区或配置前确认并停止相关运行，停止失败则保留记录。
- 移除 Project Trust 及旧信任数据，运行目录不再需要信任授权；此决定取代 ADR-0010 的项目授权要求及 ADR-0012 的批量信任确认要求，不取消只读扫描与显式执行的区分。
- 工作区运行页批量操作限定当前工作区的筛选结果；状态栏汇总全部工作区，批量操作明确标注所有工作区。
- 全局总览包含全部工作区的运行；未关联项目的配置仍呈现运行失败、进程所有权证据不足和端口暴露风险，但不呈现项目要求风险。状态栏运行条目附工作区名。

## 确认状态

用户已于 2026-09-09 确认整体设计，随后按本决定完成实现。领域术语使用 Run Configuration、Run Session 与 Run Execution，Project Run Suggestion 仍表示来自项目声明的候选配置。
