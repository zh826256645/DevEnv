# 在运行配置终端中支持持续交互 Shell

用户需要在 DevEnv 内主动输入命令，并在命令结束或按 Ctrl+C 后继续执行下一条命令。现有单次命令退出即关闭 PTY 的边界不能满足这一需求；本设计取代 ADR-0010 中“不留下空闲通用 Shell”的设计限制，同时延续 ADR-0011 的窗口关闭后驻留行为。

## 已确认的决定

- 2026-09-11，用户确认支持持续交互 Shell，连续命令共享当前目录和会话环境。
- 复用现有运行配置的终端页，并保留配置中的启动命令。
- 切换页面、工作区或关闭主窗口后继续保留 Shell 和正在执行的命令；用户显式结束会话或完全退出 DevEnv 时才终止，重新打开 App 不自动恢复执行。
- 点击「打开终端」时，没有会话就创建 Shell，已有会话就接回并提供命令输入；配置命令由「启动」按钮执行。
- 「停止」与用户在终端按 Ctrl+C 的作用相同，只中断当前前台命令并保留 Shell；「关闭终端」才结束整个会话。「重启」在同一 Shell 中先执行 Ctrl+C，再执行配置命令，不通过创建全新 Shell 实现。
- 配置命令结束后，等待输入的 Shell 仍属于活动会话，显示「终端就绪」，不表示服务仍在运行；单项停止入口切换为「关闭」。批量范围内全部活动会话均就绪时，运行页切换为「全部关闭」，状态栏切换为「全部工作区关闭」；否则批量停止按上述 Ctrl+C 语义处理。确认只处理请求时冻结的会话活动，跳过之后开始新命令的终端。
- 手动输入的命令只影响当前会话，不自动改写保存的启动命令或工作目录；手动改变目录后，配置中的目录仍保持原值。
- 点击「启动」或「重启」时，执行前切回配置指定的实际工作目录，同时保留当前 Shell 中已设置的环境变量；手动输入的命令继续使用会话当前目录。
- 前台命令运行期间，「启动」置灰，「停止」「重启」可用。重启发送 Ctrl+C 后，必须等待 Shell 恢复可接受命令的状态才执行配置命令；等待超时则提示中断未完成，不强杀，也不继续发送配置命令，避免被旧程序当作输入。
- 页面退出码和运行失败提示只跟踪通过「启动／重启」执行的配置命令；手动命令失败只在终端展示。执行中与终端就绪状态同时反映配置命令和手动命令。

## 对现有模型的影响

Run Execution 表示一次配置命令执行，Interactive Shell Session 可以跨越多次 Execution。Active Run Session 包含等待输入的 Shell，因此不能再由 Active Run Execution 的存在与否判断；终端状态、状态栏汇总及批量操作需要遵守这个区分。「停止」不能再承担关闭会话的清理职责，关闭终端和完全退出 App 仍需结束会话并清理可确认归属的进程。

## 确认状态

用户已于 2026-09-11 逐项确认 Q1–Q10，并确认开始实现。

## 实现边界

复用 SwiftTerm PTY，以会话随机标记和 Shell 原生提示符通知区分执行中与就绪；不解析可见提示符文本，也不把前台进程组等于 Shell 当作唯一就绪证据。重启中断等待为 3 秒，超时取消待执行命令。临时启动与命令脚本仅供本次 Shell 使用，目录权限为 0700、文件权限为 0600，Shell 结束后移除，不修改用户的 Shell 配置文件。

当前接入 zsh、bash、fish 和 sh。ksh 的提示符展开在 Ctrl+C 后可能跳过，无法满足可靠就绪确认；未接入的 Shell 明确报错，不降级为按时间猜测或向未知前台程序发送命令。关闭终端、删除配置及完全退出 App 继续复用进程所有权核验与清理能力；普通停止与重启不升级为 SIGTERM 或 SIGKILL。
